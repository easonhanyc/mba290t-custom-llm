and never appears here. The notebook ignores this README (`corpus/README.md` is
skipped by `load_corpus_folder`), so nothing on this page becomes training text.

Every file here was generated by [`../tools/make_extension_corpus.py`](../tools/make_extension_corpus.py)

## Two things worth knowing before reading the files

**1. Internal periods are written tight against the next word.**

You will see lines like:

```
the gate is not open .it is closed .the gate is closed .
```

That is deliberate. `chunk_text()` in the notebook splits text on
`(?<=[.!?])\s+`, so the normally-spaced version becomes **three separate training
passages**. The negation and spatial eval prompts span several clauses, so a model
trained only on one-clause passages never sees a `.` with more text after it. With
no space, the splitter leaves the line as one passage and `word_tokens()` still
reads it as `["the", "gate", "is", "not", "open", ".", "it", ...]` — the same token
sequence, kept together. Check `corpus.txt` in either run folder to confirm.

**2. The PDF's plain-text original is not in this folder.**

`08_printed_notes.pdf` is the only copy of its text inside `corpus/`. The source
lives at `../docs/pdf_source_printed_notes.txt`, outside every training input, so
the PDF contributes real passages while extraction can still be diffed against a
known original (`../tools/check_pdf_extraction.py`).

## Separation from the eval suite

`make_extension_corpus.py` refuses to write anything unless all four checks pass:

1. `reject_eval_leakage()` — the notebook's own normalized contiguous prompt
   match — finds no eval prompt in any file.
2. No proper name used anywhere in the eval suite appears in any file.
3. The reserved phrases `one bird`, `the dogs` and `yesterday she` — each of which
   *is* an entire eval prompt — appear nowhere.
4. No word pair an eval case asks the model to produce is written inside that
   case's own frame.

Shared ordinary vocabulary is expected and allowed; the test items are not here.
