# corpus/ — teaching material only

This folder is the **textbook**. The exam lives in `../evals/language_evals.json` and never
appears here. The notebook ignores this README (`corpus/README.md` is skipped by
`load_corpus_folder`), so nothing on this page becomes training text.

Every file was generated by [`../tools/make_extension_corpus.py`](../tools/make_extension_corpus.py)
and is used **only by experiment B**. Experiment A ran with this folder empty; experiment C uses
[`../corpus_seven/`](../corpus_seven) instead.

## Three things worth knowing before reading the files

**1. Internal periods are written tight against the next word.**

You will see lines like:

```
the gate is not open .it is closed .the gate is closed .
```

That is deliberate. `chunk_text()` in the notebook splits text on `(?<=[.!?])\s+`, so the
normally-spaced version becomes **three separate training passages**. The negation and spatial
eval prompts span several clauses, so a model trained only on one-clause passages never sees a
`.` with more text after it. With no space, the splitter leaves the line as one passage and
`word_tokens()` still reads it as `["the", "gate", "is", "not", "open", ".", "it", ...]` — the
same token sequence, kept together. Check `corpus.txt` in any run folder to confirm.

**2. The eval's own nouns are missing from the relational frames, on purpose.**

`book`, `bag`, `lamp`, `shelf`, `desk`, `ball`, `box` and `door` never appear inside an
above/below, left/right or inside/contains frame. They reach the vocabulary only through
`07_plain_descriptions.md`.

This is the most important design decision in the folder. An earlier version did include them,
and produced lines like `the clock is above the desk . the desk is below the clock .` — not an
eval prompt, so every upstream check passed, but it shares an 8-token suffix with one eval
prompt and was always followed by that case's answer. The model could score the case by
recalling a continuation. It scored 3/3 on spatial relations; after the fix it scores a
five-seed mean of 1.4/3. The lower number is the real one. Frames whose answer is a *relation
word* are uniquely exposed to this, because the answer does not change when the nouns do.

**3. The PDF's plain-text original is not in this folder.**

`08_printed_notes.pdf` is the only copy of its text inside `corpus/`. The source lives in
`../docs/`, outside every training input, so the PDF contributes real passages while extraction
can still be diffed against a known original (`../tools/check_pdf_extraction.py`).

## Separation from the eval suite

`make_extension_corpus.py` refuses to write anything unless five checks pass:

1. `reject_eval_leakage()` — the notebook's own normalized contiguous prompt match — finds no
   eval prompt in any file.
2. No proper name used anywhere in the eval suite appears in any file.
3. The reserved phrases `one bird`, `the dogs` and `yesterday she` — each of which *is* an
   entire eval prompt — appear nowhere.
4. No word pair an eval case asks the model to produce is written inside that case's own frame.
5. **The answer-continuation guard:** for every one of the 48 cases, no run of ≥ 3 tokens
   ending that case's prompt may appear in the generated passages followed by that case's
   answer more than half the time.

Shared ordinary vocabulary is expected and allowed; the test items are not here. Verify it
yourself with `python tools/verify_separation.py` and `python tools/leakage_ngram_audit.py`.
